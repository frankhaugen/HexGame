# Security policy

## Supported versions

This repository publishes architecture specifications and Cursor project metadata. There are no runtime releases or versioned binaries from this repo. Treat the default branch as the maintained line.

## Reporting a vulnerability

If you believe you have found a **security vulnerability** (for example, sensitive data committed by mistake, a dangerous instruction in automation, or a supply-chain concern in documented tooling), please report it **privately** so it can be addressed before public disclosure.

**Preferred:** Use [GitHub private vulnerability reporting](https://github.com/frankhaugen/HexGame/security/advisories/new) for this repository, if enabled.

**Alternative:** Open a draft security advisory or contact the repository owner through GitHub with enough detail to reproduce or locate the issue. Do not post exploit details in public issues.

## Scope notes

- The HexGame **specification** describes software architecture; it is not a network protocol registration. Implementation security in games that follow HexGame remains the responsibility of those codebases.
- Reports about **conceptual** weaknesses in the architecture (for example, missing guidance) MAY be filed as regular issues unless they clearly map to an exploitable defect in repository content.

## Response

Maintainers will acknowledge receipt when possible and coordinate a fix or mitigation. There is no SLA; this is a volunteer-maintained documentation project.
